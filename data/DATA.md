## Overview

The `data/` directory contains all data files for the OSRS AI system, including:

- **Wiki Content**: Parsed and raw wiki pages
- **Embeddings**: Semantic embeddings for wiki pages and KG entities
- **Knowledge Graph**: Entity nodes, relationships, and triples
- **GE Price History**: Complete historical price data with analytics (2.05GB)
- **Tracking Files**: Metadata for watchdog and update processes
- **Cache Files**: Attribution cache and temporary files

**Total Size**: ~5.6GB (excluding backups)

## Core Data Files

### 1. osrs_embeddings.jsonl (844MB)
**Purpose**: Semantic embeddings for all wiki pages

**Used By**:
- ✅ `api/osrs_agentic_rag.py` - Main RAG system
- ✅ `api/osrs_rag_service.py` - Legacy RAG service

**Generated By**: `scripts/create_osrs_embeddings.py`

**Format**:
```json
{
  "title": "Zulrah",
  "revid": 123456,
  "embedding": [0.123, -0.456, ...],  // 1024-dimensional vector
  "timestamp": "2025-10-02T14:11:00Z"
}
```

**Update Frequency**: Weekly (incremental) or monthly (full rebuild)

**Dependencies**:
- Reads: `osrs_wiki_content.jsonl`

### 5. price_history.db
**Purpose**: Complete Grand Exchange price history database with comprehensive analytics

**Status**: ⚠️ **NOT IN GIT** (too large - 2.05 GB)

**Used By**:
- ✅ `api/price_history.py` - Database service
- ✅ `api/price_analytics.py` - Analytics computation
- ✅ `scripts/ge_update_daemon.py` - Continuous updates
- ✅ `scripts/seed_complete_ge_history.py` - Initial seed
- ✅ `frontend/src/components/EconomicDashboard.jsx` - Economic dashboard

**Generated By**:
- Initial: `scripts/seed_complete_ge_history.py` (~40 minutes)
- Updates: `scripts/ge_update_daemon.py` (every 5 minutes)

**Data Coverage**:
- **13,796,723 historical price records** from March 2015 to present
- **4,321 unique items** with complete price history
- **4,293 items (99.4%)** with all moving averages (7d-200d)
- **Date range**: 2015-02-26 to 2025-10-05
- **Size**: 2.05 GB

**Schema**:

**Table 1: `price_history_complete`** (13.8M records)
```sql
CREATE TABLE price_history_complete (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id INTEGER NOT NULL,
    item_name TEXT NOT NULL,
    price INTEGER NOT NULL,
    volume INTEGER,                    -- NULL for pre-2020 data
    timestamp INTEGER NOT NULL,        -- Unix timestamp (milliseconds)
    data_source TEXT NOT NULL,         -- 'jagex' or 'runelite'
    has_volume INTEGER DEFAULT 0,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(item_id, timestamp)
);

CREATE INDEX idx_complete_item_time ON price_history_complete(item_id, timestamp DESC);
CREATE INDEX idx_complete_timestamp ON price_history_complete(timestamp DESC);
CREATE INDEX idx_complete_volume ON price_history_complete(volume);
```

**Table 2: `price_analytics`** (4,321 items)
```sql
CREATE TABLE price_analytics (
    item_id INTEGER PRIMARY KEY,
    item_name TEXT NOT NULL,
    current_price INTEGER,
    price_change_1d INTEGER,
    price_change_1d_pct REAL,
    price_change_7d INTEGER,
    price_change_7d_pct REAL,
    price_change_30d INTEGER,
    price_change_30d_pct REAL,
    volatility_7d REAL,
    volatility_30d REAL,
    ma_7d REAL,                        -- 7-day moving average
    ma_14d REAL,                       -- 14-day moving average
    ma_30d REAL,                       -- 30-day moving average
    ma_50d REAL,                       -- 50-day moving average
    ma_100d REAL,                      -- 100-day moving average
    ma_200d REAL,                      -- 200-day moving average
    avg_volume_24h INTEGER,
    total_volume_24h INTEGER,
    open_price INTEGER,
    high_price INTEGER,
    low_price INTEGER,
    close_price INTEGER,
    last_updated TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_analytics_item ON price_analytics(item_id);
```

**Update Frequency**:
- Daemon checks every 5 minutes
- Only fetches new data (timestamp-based)
- Auto-repairs missing analytics on startup

**Features**:
- **Complete historical data** back to March 2015
- **6 moving average periods** (7d, 14d, 30d, 50d, 100d, 200d)
- **Price change tracking** (1d, 7d, 30d with percentages)
- **Volatility metrics** (7d, 30d standard deviation)
- **OHLC data** (Open, High, Low, Close per day)
- **Volume metrics** (24h totals and averages)
- **Automatic verification** and repair on daemon startup
- **API compliant** (respects Weird Gloop guidelines)

**Example Queries**:
```python
# Get complete price history for an item
SELECT timestamp, price, volume
FROM price_history_complete
WHERE item_name = 'Twisted bow'
ORDER BY timestamp DESC
LIMIT 100;

# Get analytics for an item
SELECT item_name, current_price,
       ma_7d, ma_30d, ma_200d,
       volatility_7d, price_change_1d_pct
FROM price_analytics
WHERE item_name = 'Dragon bones';

# Find trending items (7-day change)
SELECT item_name, price_change_7d_pct, ma_7d
FROM price_analytics
WHERE ma_7d > 10000
ORDER BY price_change_7d_pct DESC
LIMIT 10;

# Get items with high volatility
SELECT item_name, volatility_7d, ma_7d
FROM price_analytics
WHERE volatility_7d > 1000
ORDER BY volatility_7d DESC
LIMIT 20;
```
